# EUROPART 3.0 — загрузка прайса (§5)

Прайс не записывает товары в момент выбора файла. Сотрудник (или admin API) делает предпросмотр и отдельно подтверждает запись. Пустые ячейки **не** затирают уже сохранённые поля.

## Форматы

- CSV UTF-8 (`,` или `;`, автоопределение). BOM снимается.
- XLSX (первый лист, ExcelJS).
- XLS не принимается.

Лимиты: 5 МБ, 2000 строк, 40 колонок.

## Admin API

Требуется заголовок `Authorization: Bearer $ADMIN_API_TOKEN` (или `x-admin-token`). Токен ≥ 16 символов в env, не в git.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/admin/imports` | multipart: `file`, `sourceType`, optional `supplierId`/`warehouseId`/`delimiter`/`templateId` |
| GET | `/api/admin/imports` | история заданий |
| GET | `/api/admin/imports/[id]` | предпросмотр строк / summary |
| POST | `/api/admin/imports/[id]` | JSON `{ "action": "preview"\|"commit"\|"rollback", "mapping"?: {...} }` |

Сопоставление колонок: артикул поставщика, OEM, доп. артикул, бренд, название, описание, категория, закупка, розница, валюта, количество, наличие, срок, фото URL. Нужен артикул **или** OEM.

## Поведение остатков и цен

- Новое предложение без явного наличия → `UNKNOWN`, `stockConfirmed=false` (витрина не пишет «в наличии»).
- Источник остатка: свой склад → `WAREHOUSE`, поставщик → `SUPPLIER`, под заказ → `ON_ORDER`.
- Закупка не копируется в розницу. Авто-розница: отдельный путь `computeRetail` на `/api/admin/offers` (курс FX + правило наценки); без настроенного курса/правила розница не выдумывается.
- Новые карточки создаются как `DRAFT` / `ANALOG` / `NEW` и не попадают в публичный каталог, пока не опубликованы.

## Откат

Откатывается только `COMMITTED` импорт один раз. Созданные этим заданием карточки удаляются, если нет других предложений; обновлённое предложение возвращается к снимку.
