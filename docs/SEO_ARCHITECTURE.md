# SEO-архитектура USAPARTS

Сайт остаётся сервисом подбора и доставки, а не витриной с остатками. Новая страница появляется только вместе с собственным текстом. Модельные URL вроде `/ford/mustang/kuzov/kapot/` описаны здесь и не опубликованы: без отдельной детали они повторяли бы общую страницу кузова.

Каждая из этих страниц есть в `src/seo/pages.ts`. Сборка пишет её HTML в `dist/<путь>/index.html` и добавляет URL в `sitemap.xml`.

## Как добавить страницу

1. Добавить объект в `src/seo/pages.ts`: свой `path`, `title`, `description`, `h1` и текст, которого нет на соседних страницах.
2. Проверить, что Title, Description и H1 не повторяются. Это делает `src/seo/pages.test.ts`.
3. Поставить внутренние ссылки из родственных страниц и с главной.
4. Запустить `npm run build`. Sitemap и prerender подхватят новый путь сами.
5. После появления домена задать `VITE_SITE_URL` и пересобрать, чтобы canonical и sitemap стали абсолютными.

## Каталог моделей

Опубликованный каталог живёт в `src/seo/catalog/` и попадает в общий список страниц. Адрес модели: `/avtozapchasti/{марка}/{модель}/`. Приоритетная категория: `/avtozapchasti/{марка}/{модель}/{категория}/`. Отдельные страницы поколений открыты только для Volkswagen Jetta Mk7, BMW X3 G01 и BMW X5 G05.

Комбинация «поколение + категория», год и фильтры в адресе не публикуются. Такой выбор остаётся на странице и уходит в форму. Черновики записаны в `seo/landing_pages.csv` со статусом `draft` и не входят в sitemap.

Старые примеры `/ford/mustang/kuzov/kapot/` этим каталогом не используются. Капот Mustang ведёт на страницу кузова модели, если кузов входит в приоритет. Подкатегории вроде «капот» и «дверь» описаны в `docs/PART_CATEGORIES.md` и не имеют собственных URL.

Блог не создан. Статью стоит публиковать по адресу `/blog/<slug>/` только с готовым текстом.

## Шаблоны страниц

### Марка

- H1: «Запчасти {марка} из США».
- Первый абзац: какие модели этой марки люди привозят и чем американская комплектация отличается.
- Блок «что указать в заявке»: модель, год, узел, VIN.
- Форма с уже выбранной маркой.
- Ссылки на VIN, доставку и 2–3 категории, которые для этой марки реально спрашивают.

### Модель

- H1: «Запчасти {марка} {модель} из США».
- Чем поколение отличается от соседнего.
- Какие узлы чаще путают.
- Форма с маркой и моделью.
- Не копировать текст марки с заменой одного слова.

### Категория

- H1 называет узел, а не «запчасти» вообще.
- Что прислать, чтобы не привезти другую ревизию.
- Чем новая позиция отличается от б/у в этом узле.
- Чего компания не обещает. Для электрики это прошивка, для двигателя — установка.

### Коммерческая посадка «марка + модель + узел»

- Один узел, одна модель.
- Фото и цена только если они настоящие и относятся к этой позиции.
- Если данных нет, страницу не открывать.

### Статья

- Прямой ответ в первых двух абзацах.
- Шаги или таблица.
- Ссылка на форму и на одну услугу, без списка всех ключей.
- Без выдуманных сроков, цен и «лучший выбор».

Темы, которые имеет смысл написать отдельно, когда будет время на проверку фактов:

- Как заказать автозапчасти из США.
- Как подобрать запчасть по VIN.
- Чем новые запчасти отличаются от б/у.
- Как проверить оригинальность по номеру.
- Как заказать двигатель из США.
- Как идёт доставка из США в Беларусь.
- Как подобрать кузов по VIN.
- Как прочитать OEM-номер.

Часть этих ответов уже стоит на служебных страницах. Статью имеет смысл писать, только если в ней больше практики, чем на услуге.

## Индексация

- В индекс идут только страницы из `pages`.
- `404.html` закрыт `noindex` и запрещён в `robots.txt`.
- Параметры `utm_*`, `gclid`, `yclid`, `fbclid`, `ysclid` для Яндекса вычищаются директивой `Clean-param`.
- CSS и JS не закрыты.
- Предпочтительный хост выбирается на сервере. Пример: `deploy/nginx.conf.example`. Пока домен не выбран, canonical остаётся корневым путём (`/ford/`), без чужого хоста.
