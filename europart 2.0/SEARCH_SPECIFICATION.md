# EUROPART 2.0 — поиск каталога

Поиск читает только опубликованные товары в активных категориях. Черновик с тем же номером не попадает в выдачу.

## Нормализация

`normalizeArticle` приводит номер к верхнему регистру и убирает пробелы, неразрывные пробелы, точки, слэши, подчёркивания и дефисы. Исходное написание остаётся в `Product.article` и `ProductIdentifier.value`.

Запрос для поиска по названию дополнительно теряет символы `%`, `_` и `\`, чтобы пользовательский ввод не стал шаблоном `LIKE`.

Пустой номер после очистки, например строка из одних дефисов, не ищет «всё подряд».

## Порядок

| Совпадение | Вес |
| --- | --- |
| `ProductIdentifier.normalizedValue` или `articleNormalized` равен запросу | 100 |
| тот же столбец начинается с запроса | 70 |
| название товара или название активного бренда запчасти содержит текст | 40 |

Внутри одного веса порядок по названию. Страница задаётся `LIMIT` и `OFFSET`.

Сравнение номера идёт по уже сохранённому нормализованному значению. Будущий импорт обязан заполнить `articleNormalized` и `normalizedValue`. Иначе номер найдётся только если он продублирован в идентификаторах.

## Индексы

B-tree на `articleNormalized` и `normalizedValue` обслуживает точное сравнение и префикс. GIN `pg_trgm` на `Product.name` и `ProductIdentifier.normalizedValue` обслуживает частичный номер и название.

Запрос собран через `Prisma.sql`. Значения пользователя остаются параметрами.

## Интерфейс

Поле на главной, в каталоге и на `/search` отправляет форму методом GET. Подсказки запрашивают тот же API с `pageSize=5` после паузы 300 мс, если введено не меньше двух символов. Состояния: «Ищем…», список, «Ничего не найдено», ошибка и отказ по частоте.

Страница `/search` показывает результат и без JavaScript: её рисует сервер.

## Чего поиск не делает

Не исправляет опечатки, не объединяет похожие товары и не подмешивает ответ поставщика. Порт внешнего каталога по-прежнему завершается ошибкой, пока адаптер не настроен.
