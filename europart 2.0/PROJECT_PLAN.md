# EUROPART 2.0 — план реализации

Новая платформа интернет-магазина автозапчастей для Беларуси. Это не перенос europart.by. Действующий сайт используется только как источник сведений о компании.

Дата сверки сайта: 3 ноября 2026.

## Принципы

- Один каталог для розницы и СТО. Цены и доступ различаются.
- Клиент не видит закупочную цену, поставщика и маржу.
- Нет товара, цены, остатка, отзыва или совместимости без подтверждённых данных.
- Нет кнопки, которая изображает успешный заказ, оплату или заявку.
- Интеграция считается подключённой только после реального вызова API.
- SEO-страница публикуется, когда у неё есть собственное содержание и ассортимент. Одинаковые тексты на тысячи URL не генерируются.
- Секреты живут в переменных окружения.

## Этапы

Каждый этап заканчивается проверкой сборки, типов и тестов. Следующий не начинается, пока текущий не зелёный.

### Этап 1. Архитектура и фундамент

Сделано в этом изменении.

- Next.js 16.4.4, React 19.3, TypeScript 5.9, Tailwind CSS 4.3.
- PostgreSQL через Prisma 7.10.1 и Docker Compose. Модели — этап 2.
- Redis в Compose и клиентский слой без вызовов со страниц.
- Zod, React Hook Form, ESLint, Prettier, Vitest.
- Модули каталога, подбора, поиска, коммерции, кабинета, B2B, склада, интеграций, контента, SEO и админки.
- Дизайн-система и честная главная без каталога.
- Закрытая индексация, пока нет ассортимента.

Выход: `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`.

### Этап 2. База данных

Модели из `DATABASE_SCHEMA.md`: пользователи, организации, автомобили, каталог, предложения, склад, корзина, заказы, заявки, контент, SEO, журнал.

Выход: миграция применяется к пустой базе, ограничения и индексы на месте, публичный запрос не может выбрать закупочную цену.

### Этап 3. Публичная часть

Главная, каталог, марки, карточка, поиск, VIN-форма с записью в базу, информационные страницы. Пустые разделы показывают пустое состояние, а не выдуманные товары.

### Этап 4. Продажи

Корзина, checkout, статусы заказа, регистрация и кабинет покупателя. Цена и остаток проверяются на сервере в момент заказа. Оплата не помечается успешной без ответа провайдера.

### Этап 5. B2B

Заявка организации, модерация, сотрудники и права, индивидуальные цены, быстрый заказ, импорт Excel, коммерческое предложение.

### Этап 6. Админ-панель

Роли, каталог, склад, поставщики, заказы, клиенты, SEO, CMS, журнал действий.

### Этап 7. SEO и скорость

Шаблоны метаданных, sitemap, robots для публичной части, canonical, schema.org, перелинковка. Индексация открывается только для страниц, которые проходят правила из `SEO_SPECIFICATION.md`.

### Этап 8. Проверка и запуск

Интеграционные и e2e-тесты заказа и B2B, мобильная вёрстка, безопасность, production-сборка, инструкция запуска.

## Решения этапа 1

- Модульный монолит на Next.js App Router. Микросервисы не нужны, пока нет отдельной нагрузки.
- Авторизация — Better Auth 1.7.15, не Auth.js. Стабильный `next-auth` остановился на 4.24.15, версия 5 по-прежнему бета (`5.0.0-beta.32`). С сентября 2025 проект сопровождает команда Better Auth и для новых систем рекомендует его. Пакет не установлен: таблицы пользователей — этап 2, вход — этап 4. Иначе появился бы маршрут, который не может завершить вход.
- Prisma 7.10.1, не Prisma 8. Восьмая версия на 3 ноября 2026 всё ещё release candidate (`8.0.0-rc.29`).
- Деньги хранятся целым числом в копейках, валюта BYN.
- Пока платформа без каталога, `robots.txt` закрывает весь сайт, а страницы отдают `noindex`.

## Юридический список для юриста

Тексты оферты, политики и согласия в репозиторий не пишутся. Юристу нужны:

- полное наименование, УНП, юридический и почтовый адрес, банк, руководитель;
- кто оператор персональных данных и где хранятся заявки;
- цели: заказ, VIN-заявка, кабинет, B2B, рассылка;
- срок хранения заявок, заказов и журналов;
- основания для розницы и для договора со СТО;
- условия доставки, возврата, гарантии на новые и контрактные детали;
- онлайн-оплата: какой провайдер и какой документ получает покупатель;
- нужно ли согласие на обработку VIN и телефона отдельным чекбоксом;
- требования к публичной оферте и дистанционной торговле в Беларуси на дату запуска.

## Что нужно от владельца

1. УНП, банк, руководитель.
2. Подтвердить часы, адрес, телефон и почту.
3. Какие способы оплаты и доставки реально работают в 2026 году.
4. Можно ли публиковать пять отзывов со старого сайта.
5. Прайс, остатки и источник данных. Пока их нет, витрина остаётся пустой.
6. Домен новой платформы и решение, остаётся ли europart.by текущим магазином на время разработки.
7. Есть ли точка в Минске. Запросы «автозапчасти Минск» в брифе есть, но компания находится в Бресте. Страница «магазин в Минске» не создаётся без реального присутствия.
8. Ключи TecDoc, поставщиков, VIN, почты, Telegram, оплаты и 1С — когда дойдём до соответствующей интеграции.
