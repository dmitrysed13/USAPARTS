# EUROPART 2.0 — архитектура

Модульный монолит. Один Next.js-процесс отдаёт страницы, принимает формы и ходит в PostgreSQL. Границы модулей держатся в коде, чтобы каталог, цены и интеграции можно было развивать отдельно.

## Как устроен запрос

1. Браузер открывает серверный компонент. Индексируемые страницы не превращаются в клиентский SPA.
2. Модуль читает только свои публичные типы. Закупочная цена не входит в тип витрины.
3. Изменение заказа, цены и остатка идёт через серверную функцию. Клиентская проверка — подсказка, не решение.
4. Внешний сервис вызывается через порт. Если адаптер не настроен, метод отклоняет промис и не возвращает успех.

Cache Components включён. Статичная оболочка страницы отдаётся сразу. Данные запроса, такие как проверка базы в `/api/health`, читаются во время запроса через `connection()`.

| search        | 3    | Артикул, OEM, название. VIN только заявкой, пока нет декодера |
| commerce      | 4    | Витринная цена, корзина, заказ                                |
| identity      | 4    | Сессия и роли сотрудников                                     |
| b2b           | 5    | Организация, сотрудники, индивидуальные цены                  |
| inventory     | 6    | Склады, резерв, поставщики                                    |
| integrations  | 6    | Порты внешних систем                                          |
| notifications | 4    | Почта и Telegram                                              |
| content       | 6    | Страницы, FAQ, статьи, отзывы                                 |
| seo           | 7    | Метаданные, sitemap, canonical                                |
| admin         | 6    | Операции сотрудников                                          |

Правило уже работает в коде: `toPublicOffer` оставляет розничную или оптовую цену и отбрасывает закупку, резерв и имя поставщика. Оптовая цена доступна только аудитории `b2b`, а аудитория становится оптовой только при статусе организации `approved`. Пустая оптовая цена не подменяется розничной.

Артикул нормализуется функцией `normalizeArticle`: регистр и разделители не мешают сравнению. Словарь опечаток и кроссы сюда не входят.

`unconfiguredSupplierCatalog` и `unconfiguredNotifications` всегда завершаются ошибкой. Тестового ответа «деталь найдена» нет.

Сгенерированный клиент Prisma лежит в `src/generated` и не коммитится. `npm run build` вызывает `prisma generate`.

## Данные и кеш

PostgreSQL — источник правды для товаров, цен, заказов и заявок. Redis позже кеширует подсказки поиска и очереди уведомлений. Кеш не подтверждает заказ и не хранит закупочные цены.

Ключ кеша имеет вид `europart:<модуль>:<части>`.

Поиск на этапе 3: PostgreSQL `pg_trgm` и полнотекст по нормализованному артикулу, OEM и названию. Внешние каталоги подключаются вторым шагом через `SupplierCatalogPort` и не смешиваются с собственным наличием, пока ответ поставщика не записан как предложение.

## Авторизация и права

С этапа 4 сессия проверяется на сервере в каждом защищённом действии. Скрытие кнопки не является проверкой.

Роли сотрудников: Super Admin, Admin, Manager, Warehouse Manager, SEO Manager, B2B Manager.

Роли внутри организации СТО другие: владелец, закупщик, бухгалтер, наблюдатель. Они не дают доступа к админке.

Пароли хранит Better Auth (по умолчанию scrypt). Секрет `BETTER_AUTH_SECRET` не попадает в клиентский бандл и в git.

## Интеграции

Порт описывает операцию. Адаптер живёт отдельно и читает ключ из окружения.

Планируются: поставщики, TecDoc, VIN-декодер, доставка, почта, Telegram, CRM, оплата, 1С. Пока ключей нет, адаптеры не создаются и в интерфейсе нет статуса «подключено».

## Безопасность

- Zod на входе форм и переменных окружения.
- Prisma параметризует запросы.
- React по умолчанию экранирует текст.
- Секреты только в окружении. `.env.example` содержит локальные пароли Compose, не боевые.
- Журнал критичных действий — модель `AuditLog` этапа 2.
- Ограничение частоты появится на формах заявок и входе. На этапе 1 публичных форм записи нет.
- Заголовок `X-Powered-By` выключен.

## Производительность

- Серверные компоненты и Cache Components.
- Шрифты Manrope и Onest через `next/font`, с подмножествами latin и cyrillic.
- Картинки товаров позже пойдут через `next/image`. Сейчас фотографий каталога нет, стоковые снимки не подставлены.
- Пагинация и индексы заложены в схему.
- Цель Core Web Vitals проверяется на реальных страницах каталога в этапе 7. Замер на пустой витрине не считается результатом магазина.
